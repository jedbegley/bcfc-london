# App notifications and app use

The Player Portal has device opt-in and category preferences. Permission is requested only after a tap. iPhone users add the app to their home screen, open it and sign in first. The manager dashboard shows first/last signed-in standalone use and counts of active registered devices, starting with this deployment. These are usage observations, not a reliable installation/uninstallation census or proof a message was read.

Managers can manually announce a published news story, an open Upcoming fixture, or a Completed match report. Each kind/target can be announced once; publishing content does not queue announcements. Closed fixtures cannot be announced as open. The news menu comes from the existing news catalogue automatically. Delivery status distinguishes provider acceptance, retryable rejection, expiry and unknown outcomes. Unknown outcomes are held for review rather than automatically resent. The browser also uses stable notification tags and stores only message IDs/timestamps for seven days to deduplicate repeated push events.

The push-only service worker has no fetch handler and caches no pages or player data. Notification clicks are restricted to same-origin news, fixture or dashboard paths. Service endpoints are allowlisted in SQL and the worker; redirects are refused. Subscription endpoints/keys are accessible only through authenticated ownership-checked functions and the backend service role, never through manager analytics. Managers receive only names, app use times and subscription counts. Logout disables this installation's subscription.

Push uses a dedicated Supabase Edge Function and encrypted Vault VAPID credentials. There is no paid notification provider, new account or Vercel environment change. The minute retry cron performs work only when deliveries are pending, and a worker handles at most twenty devices in batches of four. Existing availability email sending and its cron are independent and unchanged.

Historical rollout note: the initial pilot kept `broadcasts_enabled` false pending a physical-phone self-test. The live switch was **true at the 30 October 2026 audit**; recheck it before each release. Players and managers can opt in and test their own device. Enabling broadcasts alone sends nothing. A manager action can now queue a published-news, fixture, availability or report announcement; publication itself never queues squad news. Never send a squad notification as a deployment test. See `CURRENT_STATUS.md` for the current October private review state.

Operational limits: at most five broadcast announcements/hour, one announcement/kind/target, one self-test/player/minute, four delivery attempts, 24-hour message expiry. Per-device push permission and per-account category settings apply. Web push services and operating system settings control final delivery; acceptance is not evidence of display or reading. Expired subscriptions are disabled. A needs_review outcome requires investigation rather than a blind retry.

Validation: migration tests with @electric-sql/pglite@0.5.10; mocked service outcomes and endpoint restrictions; service-worker navigation checks; actual Deno encryption/VAPID generation; production build; existing availability/email regression tests. A real phone opt-in and receipt test is required after deployment.
